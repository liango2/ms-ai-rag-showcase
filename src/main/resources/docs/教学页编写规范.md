# 教学页编写规范（默认写法 · 写给以后写教学页的自己 / AI）

> **一句话：** 每篇教学页都必须**说人话 + 真实实现代码 + gitee commit 比对链接 + 顶部面试答题卡 + 白底主题 + Anki 式挖空记忆卡**。别只讲概念，要让学习者点进代码看到「这就是刚才那个现象的实现」。

## 默认写法（不再商量）

1. **白底中性主题**，绿色只做强调色，不做背景（旧豆沙绿已废弃）。
2. **顶部第一屏 = 面试答题卡**：30 秒口述稿 + 4~6 条考点 + 一句话收口。
3. **每页 6~12 个挖空**，遮答案关键词，优先往 `pre` 代码块和表格里放。
4. **有「事故代码 vs 修复代码」的页，必须加找 Bug 闯关**（见第二节之二）。
5. 正文可直接编辑、支持草稿、图片粘贴、导出 HTML。
6. 说人话 + 类比 + 真实实现代码 + gitee commit diff 链接 + 状态码人话含义。
7. **手机端必须能正常看**（无横向滚动、底部工具条点得到、复习弹层不遮底）——响应式已内置在共用脚本里，页面不用自己写（见第七·五节）。

## 一、页面骨架

```html
<div class="wrap">
  <div class="card">
    <h2><span class="stepno">★</span> 面试怎么答 · 30 秒口述版</h2>
    <div class="tags"><span>考点A</span><span>考点B</span></div>
    <div class="answerbox">
      <div class="lead">🎤 面试口述稿（可直接背）</div>
      <q>……</q>
    </div>
    <div class="pts">
      <div class="pt"><span class="k">机制</span><span class="v">……</span></div>
      <div class="pt"><span class="k">根因</span><span class="v">……</span></div>
      <div class="pt"><span class="k">怎么改</span><span class="v">……</span></div>
      <div class="pt"><span class="k">易错点</span><span class="v">……</span></div>
    </div>
    <div class="oneline"><b>一句话收口：</b>……</div>
  </div>
  ...原有卡片不动...
</div>
```

硬性要求：

- 答题卡必须是 `.wrap` 里的**第一张 `.card`**，放在原有内容**前面**。
- 原有卡片一张都不删、不改顺序。
- `.stepno` 用 `★`，区别于正文的数字步骤。
- `.pt` 给 **4~6 条**，每条一句话，`.k` 用 2~4 字标签（机制/根因/怎么改/易错点/排查/延伸/对比）。

## 一·五、加一章新文章（这是最常做的事，照这个顺序）

加一章要动 **4 个地方**，顺序不能乱。做完第 4 步跑一次体检命令，全绿才算完。

| # | 改哪 | 改什么 | 漏了会怎样 |
|---|------|--------|-----------|
| 1 | 新建 `NN-xxx.html` | 正文 + 挖空 + 页尾三件套 | — |
| 2 | 页面内 `<script src>` | `_learn-nav` `_notebar` `_editor` `_fsrs` `_cloze` **`_eyecare`** 六个都要引 | 洞能看不能复习；漏 `_eyecare` 则该页没有护眼主题（右下角无切换按钮、夜间一片白斑） |
| 3 | `_learn-nav.js` 的 `CH` 数组 | 加**一行** `{ n: 'NN', file: 'NN-xxx.html', title: '短标题', group: 'AI 篇' }` | 章节 tab 和上一章/下一章里看不到它 |
| 4 | `index.html` 目录 | 加一张 `<a class="item">` 卡片 | 首页点不到这一章 |
| 5 | 跑构建命令 | `node ms-demo/tools/build-learn-index.mjs` | 仪表盘分母少一章，那章永远显示 0% |

```bash
# 5. 重新生成全站洞清单 + 体检。--check 只查不写，提交前用
node ms-demo/tools/build-learn-index.mjs
node ms-demo/tools/build-learn-index.mjs --check
```

体检脚本会拦住这些错（**都是不会报错但会静默出事**的类型）：

- `[洞 id 章节号不符]` 文件是 `27-xxx.html` 却写了 `ch26.q001g` → FSRS 当成 26 章的洞，学习记录分裂
- `[洞 id 重复]` 同 id 出现在两页 → 两页共享同一个 FSRS 状态
- `[缺脚本]` 有洞但没引 `_cloze.js`
- `[缺护眼]` 没引 `_eyecare.js` → 夜间模式下这页一片白斑，右下角也没有切换按钮
- `[重复导航]` 正文里硬编码了一条已渲染的导航条（`<div class="learn-nav" data-nav-injected…>`）→ `_learn-nav.js` 见到标记会直接跳过注入，**该页不会有任何章节 tab，而且不报任何错**。25 章就是这么坏的：从别的页面复制时把整条导航条一起带过来了。新页面只写 `<script src="_learn-nav.js">`，永远不要拷渲染结果。
- `[导航缺失]` / `[首页缺失]` / `[导航悬空]` → 上面第 3、4 步漏了
- `[无章节号]` 既不在 CH 里、文件名也没数字前缀 → 仪表盘排不进位置

> **章节号的唯一权威是 `_learn-nav.js` 的 `CH` 数组，不是文件名。** 01~06 章文件名是英文的（`architecture.html` 等），构建脚本从 CH 里取号写进 `_hole_index.json`，前端只读不算。以后新章一律用 `NN-` 前缀，省事。

### 洞 id 是不能随便碰的

`data-cz-id` 一旦上线就是这洞的身份证：

- **已存在的永不要改** —— 改了等于把这个洞的复习历史清零。
- 01~06 章用的是 `chxx.a001g` 这种历史 id（建洞时还没有编号规范）。**已永久豁免，不要动** —— 改了同样清零，而且没有任何收益。
- 25 章的答题卡洞用了随机组号（`ch25.gmv3k…`）。功能完全正常，只是格式不齐。脚本不会自动改，因为改了清零。

## 二、挖空（记忆卡）

语法：

```html
<b class="mscz-mask" data-cz-g="q001g" data-cz-id="ch18.q001g"
   title="记忆卡：点击可揭示 / 遮挡">被遮住的文字</b>
```

- `data-cz-g` 是洞的组号，**同页唯一**，递增 `q001g`、`q002g`…
- `data-cz-id` 是洞的**稳定身份**，全站唯一，格式 `ch章节号.q组号`（如 `ch18.q001g`）。**已存在的 ID 永不要改** —— FSRS 的复习历史靠它关联，改了等于清空这个洞的学习记录。
- 跨多个节点遮同一段文字时，这几处**用同一个 gid 和同一个 id**（例如 `<b><b class="mscz-mask" data-cz-g="q005g" data-cz-id="ch18.q005g">base-url 和 path 是两段独立的字符串</b>文字</b>`）。同一组只有**第一个** mask 需要写 `data-cz-id`。
- 遮什么：**答案里的关键词** —— 机制名、类名、配置项、状态码、人话含义、关键数字、根因短语。
- 不遮整句（遮完看不出在考什么）。
- **代码块和表格里的挖空最有效，优先多放**，每页至少 1 个落在 `pre` 或 `<table>` 里。

## 二·五、FSRS 调度（`_fsrs.js`，已内置）

复习弹层用的是**完整的 FSRS-6 算法**（移植自官方 py-fsrs 6.3.2，用 120 场景 / 780 次复习的黄金向量逐位对齐，最大误差 5e-10）。和早期「只记次数+最近评分」的拍脑袋排序完全不同。

### 一个洞就是一个 FSRS 单元

**不要按「卡片」或「章节」调度，要按「洞」调度。** 每页 16 个洞就是 16 个独立的 FSRS 状态，各自算各自的到期时间。效果是：你复习第 18 章，FSRS 可能只把 3 个洞还给你，其余 13 个还没到期。

### 四档评分（不是三档）

| 键位 | 按钮 | 含义 | 首次评分的间隔 |
|---|---|---|---|
| `1` | 忘了 | 完全想不起来 | 1 天 |
| `2` | 有点印象 | 想起来了但很吃力 | 1 天 |
| `3` | 想起来了 | 正常回忆 | 2 天 |
| `4` | 太简单 | 秒答，特别熟 | 11 天 |

三档（少了 Easy）会让FSRS 持续低估你的记忆强度，间隔一直保守。**键位数字 = FSRS 原生 rating**，不要自己重映射。

### 刻意关掉了学习阶段

`new FSRS.Scheduler({ learningSteps: [], relearningSteps: [] })` —— Anki 默认新卡 1 分钟→10 分钟后再来一遍。我们一次要过一整章十几个洞，如果首次评分只排「10 分钟后再来」，一轮下来满屏都是待重来提示，反而看不出 FSRS 的价值。关掉后首次评分直接算出真实间隔。

### 间隔是指数增长的（这是重点）

同一个洞连续评 `Good`，间隔会这样走：

```
第 1 轮：记忆强度 2.3 天   → 下次 2 天后
第 2 轮：记忆强度 11 天    → 下次 11 天后
第 3 轮：记忆强度 46 天    → 下次 46 天后
第 4 轮：记忆强度 163 天   → 下次 163 天后
第 5 轮：记忆强度 497 天   → 下次 497 天后
```

一旦中途评 `1`（忘了），间隔立刻塌回 1 天，并在后续几轮反复徘徊 —— **这就是「精准追着快忘的点问」的实现方式**。

### 存储：四层key，结构对齐未来的 PostgreSQL

> **最终方案（已定）**：单人无鉴权（`user_id` 预留1）・洞级 FSRS + 每日软上限 25・后端 Java 纯手写 FSRS-6 核心公式落 PG。
> **现在只跑 localStorage**，但字段名和语义全部按上面这套预留，上后端时前端不用改语义。

#### 两层职责：卡管「是什么、属于哪」，洞管「记得怎么样、啥时候复习」

|层 | 表 | 管什么 | 变不变 | 前端存不存 |
|---|---|---|---|---|
| 卡 | `learn_card` | **是什么、属于哪**：页面路径、卡序号、标题、内容指纹、所属章节 | **静态**，不随学习行为变化 | **不存 HTML** —— 正文在静态文件里，DOM 是唯一渲染事实源 |
| 洞 | `learn_hole` | **记得怎么样、啥时候复习**：FSRS 的 `state / S / D / due / lastReview` + `text` 预览 | **动态**，每次评分都变 | 存，即 `msfs-card:<path>` |

**两层天然互补、不冲突**：卡是容器，洞是容器里最小的记忆单元。一个卡 N 个洞 = 1 条 `learn_card` + N 条 `learn_hole`。由此自然得到两个正确行为 —— **删卡要级联删洞**；**改标题只动卡，不影响任何洞的记忆强度**。

#### 正文只存一份：卡不存 HTML，洞只存 text 预览

| | 存不存正文 | 为什么 |
|---|---|---|
| 卡 | **不存 HTML** | 正文躺在 nginx 静态文件里。后端再存一份会出现**两份正文打架**，改了一处另一处不跟着变 |
| 洞 | **存 `text` 预览**（≤120 字，`holeText()` 裁剪） | 只为「今日到期」列表能显示「今天要复习的是哪句话」。**复习揭示仍读当前页面的实时 DOM**，所以改了正文不会出现「列表显示旧句子、复习弹出新句子」的分裂 |

代价与边界：`text` 是**镜像不是正文**，可能过期（正文改了但洞没重新评分，列表里还是旧句子）。所以面板每条都带页面名 + 留存率，点进去必然跳到该页用实时 DOM 渲染 —— **镜像只用于「认出来」，不用于「渲染」**。

卡层落库不是为了前端，是为了**跨设备、跨页面跳转时还能定位到这张卡**（前端 localStorage 按 path 隔离，换设备就没了）。

卡 id 规则 `ch{章节号}.c{卡序号}`（如 `ch18.c0`，章节号从路径解析），洞 id 就是已有的 `data-cz-id`（`ch18.q001g`）。每条 `review_log` 同时带 `cid` 和 `key`，两层都能反查。

#### 工具条两个按钮口径不同（别搞混）

| 按钮 | 口径 | 徽标含义 |
|---|---|---|
| 复习 N | **当前页** | 本页今天到期的洞数 |
| 今日到期 N | **全站跨章节** | 扫全部 `msfs-card:*`，点一条跳到对应页面 |

这是 `text` 镜像唯一的用途。

#### 跨设备同步：定案（单人无鉴权，不做向量时钟）

**FSRS 状态是链式演化的** —— 手机和电脑算出的新状态都依赖各自看到的旧状态 + 各自的 `elapsed_days`。所以**绝不能拿一份整状态覆盖另一份**，赢的那台是基于错误前置状态算的，S/D 直接被污染。

| 步骤 | 规则 |
|---|---|
| 提交 | `POST {hole_id, rating, reviewed_at}` —— **入参就这 3 个字段** |
| 判定 | 后端比较 `reviewed_at` vs 洞的 `last_review`：更新 → 接受；更旧 → **拒绝并回传最新状态**，前端刷新重渲染 |
| 重算 | 接受后基于**服务端当前状态 + 这条评分**算新状态（服务端是重算权威，返回的 card 覆盖本地） |
| 兜底 | `review_log` 全量流水是**真相**，`learn_hole` 只是最新状态的**物化视图** |

**前端一律不传** `elapsed_days` 和 `retrievability` —— 它俩都是可推导的（`elapsed = (reviewed_at − last_review)/天`；`R = FSRS(S, elapsed)`），服务端手里有 `last_review` 和 `S`，自己算就行。**少传两个可推导参数 = 直接砍掉一半分歧源**：前端和服务端最大的风险是两边算出不同的 S，把可推导字段传过去等于把风险引进设计。

查无此洞（新卡 / 离线首次创建的洞）：服务端按 FSRS 新卡默认状态初始化即可，**不需要前端带 `isNew`**——「查不到」本身就是信号。

**为什么不做向量时钟**：单人两设备几乎不可能同时评同一个洞；即使撞上，最坏结果 = 丢一次评分、间隔保守一点。对单人自用，版本向量 + 合并规则是纯负担。

#### 前后端对齐：跑同一组黄金向量（证明，不是猜）

`_fsrs_vectors.json` 是**交给后端的验收基准**（120 场景 / 780 次复习，由官方 py-fsrs 6.3.2 生成）。Java 实现完跑同一组，通过即证明逐位对齐 —— 这比「上线跑一周看两边的值会不会分叉」快且无歧义：**分叉是猜，黄金向量是证明**。

**★ 最大的坑：构造参数必须用默认值。** 向量是用官方默认构造生成的，即 `learningSteps=[1,10]` 分钟、`relearningSteps=[10]` 分钟，**没有关学习阶段**。所以首次评分会落在「1 分钟后 / 10 分钟后」这种量级（向量里能看到 `due_days=0.000694` = 60 秒）。

而**线上 `_cloze.js` 传的是空数组**（刻意关掉学习阶段，否则一整章十几洞满屏都是「10 分钟后再来」）。所以**直接拿本向量去验线上配置必然不通过 —— 这是预期的，不是 bug**。两条路选一条：

| 方案 | 构造参数 | 比对内容 |
|---|---|---|
| **A. 验核心公式**（推荐） | 默认 steps | S / D / state / due_days 全比，能验到 Learning/Relearning 的分钟级 step 逻辑 |
| B. 验线上行为 | `learningSteps:[], relearningSteps:[]` | 只比 S / D / state，**跳过 due_days** |

容差：`S < 1e-6`、`D < 1e-6`、`state` 完全相等、`due_days < 1e-4`（= 8.64 秒；向量只保留 6 位小数，而有意义的最小刻度是「1 分钟」）。

其他已知陷阱：`_DECAY = -w20`、`_FACTOR = 0.9^(1/_DECAY) - 1`；新卡 `state=0` 要先归一成 `Learning(1), step=0`；**`elapsed_days` 必须取整数天（向下取整）**，用精确小数天会让 S 偏约 0.4%，且偏差随 S 增大而放大。

#### 离线评分：待同步队列（已实现，`SYNC_MODE='local'` 时空转）

| 环节 | 规则 |
|---|---|
| 入队 | 离线评分进本地待同步队列，标 `pending` |
| 提交 | 连上后**按 `reviewedAt` 升序**、**严格串行**提交，失败重试 |
| 被拒 | 标 `rejected` **留档不重放** —— 时间线正确让位，等该洞到期时当场重评即可 |
| 重放 | **不做离线队列重放** |

三个关键设计点：

1. **队列没有单独一份数据** —— 它就是 `review_log` 里的 `pending` 条目，状态写在每条流水自己的 `sync` 字段上。另存一份数组就会出现「两份流水」不一致，那正是要避免的。
2. **升序是硬要求，不是优化** —— 后端拿 `reviewedAt` 比 `last_review` 判接受/拒绝，乱序提交会让同一段时间内的两次评分互相顶掉。同理必须**串行**，并发会让顺序失效。
3. **`rejected` 语义是「服务端明确拒绝」，网络不通不算** —— fetch 抛错时留在 `pending` 等重试。写混了会导致断网时把评分全标成 rejected。

工具条上有「待同步 N」（琥珀色）和「需重评 N」（红色）两个按钮，local 模式下永不出现。`queueDrain()` 排空后必须 `refreshBadge()`，否则按钮停在旧数字上——被拒了但界面不告诉你。

后端就绪后只需：`SYNC_MODE` 切 `'remote'` + 注入 `submitReview(req) -> Promise<res>`，上层逻辑不用改。

#### key 对照

| localStorage key | 未来对应表 | 语义 |
|---|---|---|
| `msfs-card:<path>` | `learn_hole` | 每个洞的 `{state, step, stability, difficulty, due, lastReview, uid, sv}` |
| `msfs-log:<path>` | `review_log` | 复习流水，**只追加不修改** |
| `msfs-day:` | —— | **全站**当日用量 `{day, count, again}`，跨天自动归零（不带path，因为限额是跨章节的总量） |
| `mscz-score:<path>` | —— | 旧版遗留，仅供 `migrateLegacy()` 一次性迁移 |

每条 `card` 带 `uid:1`（用户预留位，将来换成登录态即可，其余代码不动）+ `sv:1`（schema 版本，换 FSRS-7 时靠它判断历史记录要不要重算）。

`review_log` 每条含 `uid / sv / path / cid / key / rating / reviewedAt / day / mode / fsrsVersion / pre·postStability / pre·postDifficulty / elapsedDays / scheduledDays`。**将来迁到 PG 可以原样导入并重放**，也能拿来训练每用户的 FSRS 参数（`fsrs_params_version`：21 = FSRS-6，35 = FSRS-7）。

旧数据迁移：老版本只存了 `{n:次数, s:最近评分}`，没有时间序列，无法反推真实轨迹。`migrateLegacy()` 按「假设每3 天复习一次」重建一个粗略起点，从迁移之日起的新记录才有精确轨迹。`n=0`（从没复习过）不迁移。

### 每日软上限 25

复习弹层右上角常驻「今日 N/25」，工具条「复习」按钮的 `title` 里也有全站用量。

- **只提示，不拦。** 到 25 时数字转琥珀色，超过转红色并提示「明天再来更划算」，但仍可继续评分 —— 硬拦只会让人想绕过去。
- 依据是记忆科学的 spaced repetition 惯例：一天硬灌太多，短期记得住、长期反而忘得更快。
- 计数是**全站**的，不按页拆分。

### 「复习」按钮上的数字是「今天到期」

不是全页洞总数，而是 FSRS 排出来**今天该问的洞数**。排期没到的洞本来就不该现在问。全部没到期时按钮只显示「复习」，`title` 会提示可以先读正文。每评一个洞徽标会实时重算 —— 刚复习过的洞被排到未来，数字会当场掉下来。

## 四、找 Bug 闯关（面试 L4 层，只给有对比素材的页加）

### 接入方式

组件自带样式注入，不用额外加 CSS。页面里加挂载点和脚本：

```html
<div class="bq-mount"></div>
<script src="/learn/ms-demo/_bugquest.js" defer></script>
```

然后：

```html
<script>
document.addEventListener('DOMContentLoaded', function () {
  BugQuest.mount('.bq-mount', {
    title: '找 Bug 闯关 · N 段真实配置，你先判',
    desc: '每关给你一段真实配置，先判断会不会出事，判完给证据。',
    onAllClear: '通关后的收口话术。',
    levels: [
      {
        name: '第 1 关 · 简短场景名',
        cfg: [ '配置行1', '配置行2' ],
        ask: '这段配置调 XXX，会返回什么？',
        options: [
          { t: '选项文本', ok: true,  why: '为什么对/错 —— 要讲清机制，不只是结论' },
          { t: '选项文本', ok: false, why: '为什么不对' }
        ],
        proof: { type:'sim', base:'<base-url>', path:'<path>', good:'<服务端认可的正确URL>' }
      }
    ]
  });
});
</script>
```

### `proof.type` 三种

| type | 用途 | 字段 |
|---|---|---|
| `sim` | 纯字符串拼接推演，**永远可用，不依赖后端** | `base` / `path` / `good` |
| `text` | 纯文本证据（报错输出、配置对比） | `text` |
| `live` | 需要真调接口时先占位，真机按钮由 `live` 字段生成 | 配合 `live` 用 |

### 关卡设计要求

- **每关只考一个判断**，选项 3~4 个。
- **`why` 必须讲机制**，不能只说「错了」。例：「base-url 的 /v1 + 默认 path 的 /v1/embeddings = /v1/v1/embeddings」。
- **`options[].ok:true` 只能有一个。**
- **难度递进**：照抄文档出错 → 正确写法 → 坑中坑 → 过度修正。参考第 18 章四关。
- 关卡数 3~6 关为宜。

### 机制说明（已实现，别改坏）

- **3 颗心**，答错扣 1，**跨关累积**；扣光必须重刷本关，「下一关」不给过。
- 答完一关即锁选项，防止蒙答案。
- 「下一关」**只有答对才解禁**，未答对时按钮文案是「先判断再继续 →」且置灰。
- 进度存 `localStorage`，按页面路径隔离。`BugQuest.reset()` 可清。
- 通关后出现全绿总结卡，可「再刷一遍」。

## 七·五、移动端适配（已在共用脚本里内置，页面本身不用写）

三处共用脚本已自带 `@media(max-width:760px)` / `max-width:1000px` 规则，**新页面不需要再写响应式**，但要知道它们解决了什么：

| 文件 | 窄屏做了什么 | 不加会怎样|
|---|---|---|
| `_notebar.js` | `.ms-layout` 纵向排列时补 `align-items:stretch` + 子项 `width:100%`；宽表格改横向滚动；超长代码强制换行 | 整页被长代码/宽表格撑到 600~900px，手机上左右乱晃 |
| `_editor.js` | 工具条改贴底全宽、按钮换行成两排、状态文字独占一行；新增 `⌨ 快捷键` 面板 | 9 个 nowrap 按钮把fixed 工具条撑到 ~1120px，两端按钮点不到 |
| `_cloze.js` | 复习弹层改全屏铺顶、圆角在上、`max-height:88vh`；评分按钮换行成两排 | 弹层被工具条压住底部，看不到「下一洞」 |

写新页面时的两条硬约束（**别写进页面 CSS**）：

1. 不要给 `.wrap` / `.ms-layout` 设固定 `min-width` 或 `width`，共用脚本已经接管。
2. `<meta name="viewport" content="width=device-width, initial-scale=1.0">` 是必须的，缺了手机上整页按 980px 渲染。

## 八、交互说明

- 选中正文任意文字 → 点工具条「做记忆卡」→ 挖空；点遮罩可揭示。
- 点「复习」进入 FSRS 式弹层：按到期时间逐洞推进，空格揭示，`1/2/3/4` 四档评分（忘了 / 有点印象 / 想起来了 / 太简单），**键位数字 = FSRS 原生 rating**。
- 弹层顶部有**洞进度点阵**：当前洞是放大绿点，已走过的是浅绿点，右边文字写「记忆强度 X 天 · 当前留存率 Y% ★★★」——一眼看清这个洞的记忆状态。
- 弹层右上角常驻「今日 N/25」：每日软上限，只提示不拦。
- 工具条「复习 N」的 N 是**本页今天到期的洞数**（不是全页总数），每评一个洞实时重算。
- 工具条「今日到期 N」是**全站跨章节**口径，点开是一张汇总单，点某条跳到对应页面开始复习 —— 这是`text` 镜像唯一被用到的地方。
- 点工具条「⌨ 快捷键」看全部键盘快捷键；每个按钮也都有 `title` 悬停提示。
- FSRS 状态与复习流水记在 `localStorage`，按页面路径隔离；`msfs-day:` 是全站共用的当日计数。
- 编辑正文草稿存 `localStorage`；草稿异常会自动回滚，`Ctrl+Shift+R` 强制清草稿刷新。
- 正文支持 Ctrl+V贴图、缩略图、拖拽缩放、源码视图、导出 HTML。
